The problem

The goal was a system where someone at a manufacturing company could ask a question in plain Korean or English and get an answer out of a production database, without knowing SQL or the schema.

The obstacle was data. We had a few dozen real sample queries and nothing else — no training set, and no database we were allowed to develop against. Everything had to be constructed before any modelling could start.

Building the dataset

Working with a graduate student, we built a synthetic database consistent with the client's samples, then generated 5,000 question–SQL pairs against it: programmatic generation for the query structures, LLM paraphrasing for natural-language variation, and manual validation of the result.

Measuring coverage

A generated dataset can look large and still be narrow. Because we controlled generation, we could also inspect it: I proposed measuring diversity through the distribution of pairwise cosine similarity between question embeddings, and using its shape to detect where generation was clustering — then correcting the sampling and regenerating.

The system

We benchmarked several open-source models — Qwen2.5, Llama, and Codestral among them — and fine-tuned Qwen2.5, which performed best on our task.

The delivered system did not use the fine-tuned model. The client wanted the freedom to swap in a commercial API later, so we built a model-agnostic few-shot pipeline that draws on the training set without depending on any particular model's weights. It gave up some accuracy for the ability to change models without retraining.
